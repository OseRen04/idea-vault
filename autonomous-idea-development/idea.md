# 自律開発スタジオ

## 基本情報
- agent_development: denied
- 状態：構想
- 優先度：未設定

## 概要
本システムは、GitHubに保存した企画を自律的に開発する。
ユーザーは、ChatGPTで企画を登録する。
ユーザーは、開発を許可する企画と優先度を指定する。
ユーザーは、自動開発を行う曜日と時間帯を指定する。
GitHub Actionsは、指定された時間帯に開発処理を起動する。
Symphonyは、開発タスクとCodexの実行を統括する。
Codexは、企画に基づいて設計・実装・テストを行う。
本システムは、GitHubに開発成果と進捗を保存する。
翌回の実行では、本システムが未完了の開発を再開する。

## 背景・課題
ユーザーは、企画を実装するたびに開発指示を出す負担を減らしたい。
ユーザーは、就寝中などの時間を開発に活用したい。
一方、一般的な対話型の開発支援は継続的な指示を要する。
したがって、本システムは無人での継続開発を目指す。

## 対象ユーザー
本システムは、ChatGPTとGitHubを利用する個人を対象とする。
将来的には、複数ユーザーへの提供も視野に入れる。
ユーザーは、自身のChatGPT契約を使ってCodexを利用することを望む。

## 解決方法
ユーザーは、ChatGPTのIdea Vaultで企画を管理する。
Idea Vaultは、企画ごとのファイルをGitHubに保存する。
GitHub Actionsは、ユーザー単位のスケジュールで処理を開始する。
GitHub Actions内のスクリプトは、開発許可と優先度を判定する。
GitHub CLIは、初回に企画専用のPrivateリポジトリを作成する。
GitHub CLIは、初期ファイルと開発用Issueを生成する。
2回目以降は、GitHub CLIが既存のリポジトリとIssueを再利用する。
GitHub Actionsは、実行環境内でSymphonyを起動する。
Symphonyは、Issueを取得してCodexの開発作業を管理する。
Codexは、規定の開発手順に従って作業を進める。
本システムは、コードと残課題をGitHubに保存する。
GitHub Actionsの終了後も、GitHubは開発成果を保持する。

## 主な機能
- Idea Vaultは、企画書・議論履歴・自由形式メモを管理する。
- ユーザーは、企画ごとに開発許可と優先度を設定する。
- ユーザーは、ChatGPTで開発する曜日と時間帯を設定する。
- GitHub Actionsは、ユーザー単位の設定時刻に処理を起動する。
- 企画選定スクリプトは、許可済みの未完了企画を選ぶ。
- 企画選定スクリプトは、継続企画と優先度を考慮する。
- GitHub CLIは、PrivateリポジトリとIssueを準備する。
- Symphonyは、Issue・作業領域・Codexの実行を管理する。
- Codexは、企画の設計・実装・テストを実施する。
- 本システムは、開発成果と未完了作業をGitHubへ保存する。
- 次回の実行は、既存のコードとIssueから開発を再開する。
- ユーザーは、ChatGPTから開発結果を確認する。

## 技術・制約
- ユーザー向けUIはChatGPTだけとする。独自Web UIは作成しない。
- 企画管理には既存のIdea Vault Skillを使用する。
- 企画フォルダはリポジトリ直下の `<idea-id>/` とする。
- 各企画は `idea.md`、`discussions.md`、`memo.md` を持つ。
- `memo.md` は自由形式とする。AIはメモ本文を自動整形しない。
- 開発許可は `agent_development` で管理する。
- 開発許可の値は `allowed` または `denied` とする。
- 設定なし・不正値・新規企画の初期値は `denied` とする。
- ユーザーだけが明示的な指示で開発許可を変更できる。
- 状態は「構想」「開発中」「完了」「中断」とする。
- 優先度は正の整数または「未設定」とする。
- 数値が小さい企画ほど開発を優先する。
- 自動開発の時間設定は企画単位ではなくユーザー単位とする。
- 時間設定の保存先候補は `settings/development-schedule.yaml` とする。
- 定期実行と計算環境にはGitHub Actionsを採用する。
- GitHub操作にはGitHub CLIと適切な認証情報を使用する。
- 開発タスクの管理にはOpenAI Symphonyを採用する。
- コーディングにはSymphonyが起動するCodexを使用する。
- 開発対象には専用のPrivateリポジトリを作成する。
- 独立した有料クラウド基盤は使用しない。
- ユーザーのPCや自宅サーバーを実行環境にしない。
- GitHub Actionsの無料枠内での運用を目指す。
- 追加のOpenAI API従量課金を発生させない構成を目指す。
- ChatGPT契約によるCodexの無人認証は未検証である。
- Symphonyの安全な停止・再開は未検証である。
- MCPサーバーは初期実装の必須要件としない。
- 現時点では企画の自動開発を開始しない。
